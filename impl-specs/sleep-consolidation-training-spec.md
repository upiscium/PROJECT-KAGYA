# Sleep Consolidation Training Pipeline 設計メモ

## 目的
`sleep_consolidation.py` の後段として、生成済みの `JSONL` データを用いて学習を実行し、LoRA アダプタを保存する。

## 範囲
- 入力: 圧縮済みの学習データ `JSONL`
- 処理: 学習データの読み込み、学習、アダプタ保存
- 非目標: 記憶圧縮、事実抽出、データ生成そのもの

## 公開インターフェース

### `train(dataset_path, model, output_dir)`
- `JSONL` データを読み込み、学習を実行する。
- 返り値は学習結果の要約情報とする。

### `save_adapter(output_dir)`
- 学習済み LoRA アダプタを保存する。
- 保存先は指定ディレクトリとする。

### `load_adapter(base_model, adapter_dir)`
- 保存済みアダプタがある場合、ベースモデルへアタッチする。
- 起動時の復元処理として扱う。

## 学習データ要件
- 各行は次のスキーマを満たす。
```json
{
  "input": "str",
  "thought": "str",
  "output": "str",
  "source_ids": ["str"],
  "confidence": 0.0,
  "status": "confirmed"
}
```
- `status` は `confirmed` のみを想定する。
- `thought` は空であってはならない。
- 学習対象から `conflicted` と低信頼候補を除外する。

## 学習パイプライン
1. `JSONL` を読み込む
2. 形式検証を行う
3. 学習可能な例だけを抽出する
4. モデルに入力する
5. LoRA アダプタを更新する
6. 学習結果を保存する

## モデル契約
- ベースモデルは学習可能な causal language model とする。
- LoRA / PEFT を使ってアダプタ学習する。
- 学習実行は後段モジュールから注入された trainer に委譲してよい。

## エラー時の挙動
- `JSONL` が読めない場合は明示的に失敗する。
- 学習に失敗しても、入力データと中間生成物は保持する。
- 保存失敗時は、学習済み状態を破棄せずに失敗を返す。

## 境界条件
- 空データセットは失敗ではなく、安全に終了する。
- 無効な `thought` を含む例は除外する。
- 長すぎる例は事前に分割済みであることを前提とする。

## 仕様テスト観点
- `JSONL` を読み込めること
- 無効例が除外されること
- 学習後にアダプタが保存されること
- 保存済みアダプタを再ロードできること
- 空データセットで安全に終了すること

## 非目標
- 記憶圧縮
- `DB1` / `DB2` の管理
- 学習データ生成
- 学習品質の最適化

## 補足
- この段階は「データ生成の後処理」として扱い、学習と保存を分離する。
