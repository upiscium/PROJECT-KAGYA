# Multimodal FastAPI Interface 設計メモ

## 目的
画像、音声、動画、テキストを受け取れる FastAPI ベースの統一入力インタフェースを定義する。

## 位置づけ
- 入力受付: 本書
- モダリティ別前処理: 後段モジュール
- 推論・記憶・検索: 別責務

この段階は、受け口を整理し、モダリティごとの責務を分離する。

## 公開インターフェース

### `MultimodalIngestAPI`
- マルチモーダル入力の入口とする。

### `POST /ingest`
- テキストとファイルをまとめて受け取る。
- 画像、音声、動画を `UploadFile` で受ける。
- 返り値は受理結果の要約とする。

### `POST /chat`
- テキスト中心の対話入力を受ける。
- 返り値は会話入力の受理結果とする。

### `WS /stream`
- 逐次応答やストリーミング処理のための WebSocket エンドポイントとする。

## 入力ルール
- テキストは JSON か form field として扱う。
- 画像、音声、動画は `UploadFile` を使う。
- モダリティごとにメタデータを明示する。

## モダリティ契約
- `image`: 画像ファイル
- `audio`: 音声ファイル
- `video`: 動画ファイル
- `text`: 自由入力テキスト

## 境界条件
- どれか1種類だけでも受理できる。
- すべて空の場合は失敗する。
- 動画はサイズ制限を設ける。
- WebSocket は逐次応答専用とする。

## エラー時の挙動
- 不正な MIME type は拒否する。
- サイズ超過のファイルは拒否する。
- 入力が不足している場合は明示的に失敗する。

## 実装上の留意点
- 受信後の重い処理は API 本体から外す。
- 入力正規化層を1枚挟む。
- テキストとファイル処理を分ける。
- 動画は非同期処理前提で扱う。

## 仕様テスト観点
- テキストのみの受理ができること
- 画像、音声、動画の受理ができること
- 空入力が失敗すること
- サイズ超過が拒否されること
- WebSocket で逐次応答できること

## 非目標
- モダリティの推論処理
- 記憶保存
- 検索処理
- メディア変換や圧縮の実装

## 補足
- このインタフェースは、後段の推論・記憶・学習へつなぐための入口に限定する。
