# PROJECT-KAGYA: 主観AIアーキテクチャ 詳細実装仕様書

## 1. プロジェクト概要
本プロジェクトは，計算機上に自律的なAI人格(主観)を創発させることを目的とする．静的なLLMに対して"予測誤差(Loss)からの情動生成""アロスタシス(動的適応)"を実装し，さらに**"思考モデル(Reasoning Model)によるネイティブな内言"と"Dual VectorDB(短期エピソード記憶と長期意味記憶の階層構造)"，そして"QLoRAを用いた思考プロセスと思考結果の睡眠時学習"**を統合することで，生物学的に妥当な自律エージェントを構築する．

## 2. システム要件と技術スタック
- 言語: Python 3.10+
- パッケージ管理: uv
- 主要ライブラリ:機械学習・推論: torch, transformers, accelerate
- 量子化・学習: bitsandbytes, peft, trl
- 記憶システム: chromadb, sentence-transformers
- 推奨ベースモデル: deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B 等のローカル稼働可能な推論(Thinking)モデル．

これによりネイティブな <think> プロセスを"意思決定の舞台"として活用する．

## 3. システムアーキテクチャとデータフロー

### 3.1 Dual Memory System(階層型記憶)
- DB1 (Hippocampus / 海馬): 短期・エピソード記憶バッファ．直近の会話生ログと，その時の情動(Valence/Arousal)を保存する．
- DB2 (Cortex / 大脳新皮質): 長期・意味記憶．睡眠時にDB1から抽出された"ユーザーに関する事実"や"普遍的なルール・関係性"を永続保存する．

### 3.2 オンラインフェーズ(Main Chat Loop: 覚醒時)
- Surprisal Calculation: ベースLLMを用いて新規入力の予測誤差(Loss)を計算する．
- Emotion Engine: Loss値からAIのコア・アフェクト(Valence/Arousal)と動的しきい値を更新する．
- Dual Retrieval: DB1(直近の文脈・感情)とDB2(長期的な事実・ルール)の両方から関連記憶を検索する．
- Conscious Reasoning: 情動と2つの記憶をプロンプトに統合し，思考モデルにネイティブな推論(<think>タグ)を行わせ，最終返答を生成する．
- Memory Encoding: 今回のエピソード(入力，出力，情動)をDB1に保存する．

### 3.3 オフラインフェーズ(Sleep Cycle: 睡眠時)
- Memory Consolidation (DB1 → DB2): DB1に溜まったエピソードをLLMで要約・事実抽出(Knowledge Extraction)し，メタデータと共にDB2へ移行．移行が完了したDB1の古いデータは破棄する(忘却)．
- Dream Generation & QLoRA Tuning: 情動が大きく動いたエピソードから"理想的な思考プロセス"と"返答"のペアを生成し，4-bit量子化ベースモデルに対してQLoRAで重みを更新する．これにより，メタ認知能力と暗黙知(性格)を同時に成長させる．

## 4. 各モジュールの詳細設計(エージェント向け実装指示)
以下のクラス群を独立したモジュールとして実装し，最終的に main.py で結合すること．

### 4.1. 予測誤差計算モジュール (surprisal_calculator.py)
- 機能: LLMのフォワードパスを利用し，新規入力の驚き度(Loss)を計算する．
- 重要制約要件: labels テンソルにおいて，過去の文脈(context_text)部分を -100 でマスクすること．これによりAI自身の過去の発言やプロンプトに対するLoss計算を除外する．勾配計算は不要なため with torch.no_grad(): ブロック内で実行する．

### 4.2. 情動・アロスタシスモジュール (emotion_engine.py)
- クラス名: EmotionEngineAllostasis
- 機能: ヴント曲線とアロスタシスを用いて，Loss値を情動に変換する．
- 状態変数: optimal_loss (初期値: 2.5), adaptation_rate (初期値: 0.15)
- 計算ロジック(厳密に以下の数式を実装すること):
    - 覚醒度の更新 ($A$: Arousal): $A_{new} = \max(0.0, \min(1.0, A_{current} \times 0.8 + loss \times 0.2))$
    - ヴント曲線による一時的な快不快 ($W$): $W = 1.0 - 0.3 \times (loss - L_{opt})^2$
    - 快不快の更新 ($V$: Valence): $V_{new} = \max(-1.0, \min(1.0, V_{current} \times 0.4 + W \times 0.6))$
    - しきい値の動的更新 ($L_{opt}$: optimal_loss): $L_{opt\_new} = (1.0 - \alpha) \times L_{opt\_current} + \alpha \times loss$ (※ $\alpha$ は adaptation_rate)

### 4.3. 階層型記憶モジュール (dual_memory_system.py)
- クラス名: DualMemorySystem
- 機能: ChromaDBを用いて hippocampus コレクションと cortex コレクションを管理する．
- メソッド:
    - save_episodic(user_input, response, valence, arousal): DB1にテキストとメタデータを保存．
    - retrieve_context(query): DB1とDB2の両方からTop-K検索を行い，プロンプト挿入用の文字列としてフォーマットして返す．
    - consolidate_to_semantic(llm_pipeline): 睡眠時に実行．DB1の生ログをLLMに渡し"ユーザーに関する永続化すべき事実(Semantic Knowledge)"を抽出させてDB2に保存．処理後，DB1の該当レコードを削除する．

### 4.4. 意識の舞台・思考モジュール (conscious_agent.py)
- クラス名: ConsciousAgent
- 機能: 推論モデルの能力を引き出すシステムプロンプトの構築と生成実行．プロンプト設計要件:システムプロンプトに現在の Valence (快/不快), Arousal (覚醒度), および DB1/DB2からの検索結果 を明記する．指示として**"出力の最初に必ず <think>...</think> タグを使用し，自身のValenceをプラスに保ちArousalを適正化するための戦略と，DB2の長期記憶との整合性を評価・計画してから，最終的な返答を生成せよ"**と強制する．

### 4.5. 睡眠・QLoRA学習モジュール (sleep_consolidation.py)
- クラス名: SleepCycleManager
- 機能: バッチ処理として実行される，思考プロセスと暗黙知のQLoRA学習．プロセス:Triage: DB1から情動が大きく動いたエピソード(例: Arousal > 0.7 または |Valence| > 0.6)をメタデータフィルタリングで抽出．
- Dream Generation: 抽出したエピソードをLLMに渡し，"理想的な思考プロセス"と"返答"のペアを生成させ，JSONLデータセット(dream_dataset.jsonl)を作成する．
    - スキーマ:
        ```json
        {"input": "str", "thought": "str", "output": "str"}
        ```
- QLoRA Tuning:bitsandbytes を用いてベースモデルを4-bit (nf4, bfloat16) でロード．peft.prepare_model_for_kbit_training を適用．trl.SFTTrainer を使用．ハイパーパラメータ: r=8, lora_alpha=16, lora_dropout=0.05, learning_rate=2e-5, num_train_epochs=3.プロンプトフォーマット(重要): 学習データは以下の文字列フォーマットに結合して学習させること．
```plaintext
ユーザー: {input}
私: <think>
{thought}
</think>
{output}<eos>
```

学習完了後，LoRAアダプタを ./kagya_subjective_adapter に save_pretrained で保存．

## 5. 実装とテストのフェーズ定義(エージェント向け指示)
コーディングエージェントは以下の順序で進行し，各フェーズ完了ごとに動作確認を行うこと．
- Phase 1: uv環境構築とコアロジック実装uv init を実行．uv add torch transformers accelerate bitsandbytes peft trl chromadb sentence-transformers で依存関係を解決．surprisal_calculator.py と emotion_engine.py を実装し，ダミーデータで数式が正しく動作するかユニットテストを実行．
- Phase 2: Dual Memory と Thinkingエージェントの実装dual_memory_system.py を実装．2つのDB間のデータ移行(Consolidation)のテストを行う．conscious_agent.py を実装し，Thinkingモデルが <think> タグ内で適切に情動評価と事実参照を行っているかテキスト出力を検証．
- Phase 3: 統合チャットループの構築main.py にオンラインループを構築．推論時にも bitsandbytes で4-bit量子化ロードを行い，VRAMを節約しつつ"Loss計算"と"テキスト推論生成"が同居して動作するようにパイプラインを調整する．
- Phase 4: オフライン睡眠・QLoRAモジュールの実装sleep_consolidation.py を実装．少量のダミーデータセットでQLoRA学習を回し，エラーなく完了するかテスト．main.py のロード処理を改修し，保存されたLoRAアダプタが存在する場合は量子化ベースモデルに PeftModel.from_pretrained を用いてアタッチして起動するロジックを追加する．
