# 4bit Quantized Model Load - Idea Review

## 対象
`sleep_consolidation_training` や `qlora_training` で使う、4bit 量子化モデルのロード処理。

## 何を解くか
- 学習前にベースモデルを 4bit で読み込めるようにしたい。
- VRAM 使用量を抑えつつ、QLoRA 学習の前提を整えたい。
- 学習本体とは別に、ロードだけを安定して扱いたい。

## 良い点
- 4bit 化で大きいモデルでもローカル運用しやすくなる。
- `peft` / `bitsandbytes` と相性がよい。
- 学習前処理とロードを分離できるので、責務が明確になる。

## 先行事例との近さ
- Hugging Face の `BitsAndBytesConfig` を使う一般的な QLoRA 構成に近い。
- `transformers` + `peft` + `bitsandbytes` の標準的な流れに沿う。

## リスク
- `bitsandbytes` が環境依存で動かないことがある。
- CUDA / GPU がないと実運用が厳しい。
- 4bit ロードと学習設定がズレると、後段で失敗しやすい。
- テスト環境では実際の量子化ロードを再現しにくい。

## 実現性
- 実現性: 中〜高。
- 難易度: 中。
- 工数感: 小〜中。

## 実装時の注意
- ロード処理は学習本体と分ける。
- 量子化設定は明示的に持たせる。
- 4bit ロード失敗時のフォールバックを決める。
- `prepare_model_for_kbit_training` とセットで扱う。

## 現実的な進め方
1. 4bit のロード関数を切り出す
2. 設定を明示する
3. 学習前処理と接続する
4. 実環境でだけ量子化を使う

## 結論
- 4bit ロードは、QLoRA を現実的に回すための重要な前提。
- ただし単独ではなく、学習前処理とセットで設計するのがよい。
