# SUBJECTIVE AI ARCHITECTURE v1 - Idea Review

## 目的
`impl-specs/v1.0.md` を、実装前のアイデアとして分解し、実現可能性・リスク・先行事例との近さをざっくり整理したメモ。

## 全体所感
- 方向性は一貫していて、`loss -> emotion -> retrieval -> reasoning -> consolidation` の循環も理解しやすい。
- ただし、研究アイデアとしては面白いが、各要素が強く相互依存しているため、最初から全部つなぐと原因切り分けが難しい。
- MVP は「会話 + 双層記憶 + 簡易情動更新」までに絞るのが現実的。

## 1. プロジェクト概要
- 狙い: 主観らしさを、予測誤差・情動・記憶・睡眠学習で再現する。
- 評価: 発想は魅力的だが、`主観` の定義が曖昧だと成功判定ができない。
- リスク: 生物学的妥当性を目標にすると、実装より仮説検証が主題になりやすい。

## 2. 技術スタック
- `Python + uv + torch + transformers + chromadb` は妥当。
- `bitsandbytes / peft / trl` もローカル小規模モデルには相性がよい。
- `DeepSeek-R1-Distill-Qwen-1.5B` はローカル推論の候補として筋がよいが、会話品質と学習コストのバランスは要確認。

## 3. システムアーキテクチャ

### 3.1 Dual Memory
- 良い点: 短期エピソードと長期意味記憶を分ける設計は自然で、デバッグもしやすい。
- 懸念: 何を「事実」とみなして DB2 に上げるかが最重要で、ここが曖昧だと汚染が起きる。
- 先行事例との近さ: RAG + long-term memory 系の延長としてかなり実装しやすい。

### 3.2 Online Loop
- 良い点: `surprisal -> emotion -> retrieval -> generation` の順序は制御しやすい。
- 懸念: `loss` を毎回厳密に計算するとコストが高く、会話テンポを落とす可能性がある。
- 現実案: 全入力でなく、重要ターンのみ算出する軽量化が必要。

### 3.3 Sleep Cycle
- 良い点: 学習と推論を分離するのは運用上きれい。
- 懸念: QLoRA を頻繁に回すと、過学習・忘却・品質劣化の管理が難しい。
- 現実案: 最初は「要約と記憶圧縮」だけにして、学習は後段に分けるのが安全。

## 4. モジュール別評価

### 4.1 surprisal_calculator.py
- 実現性: 高い。
- 注意点: `context_text` の `-100` マスクは必須だが、テンプレート依存でズレやすい。
- リスク: `loss` をそのまま驚き度とみなすのは雑で、会話長やトークナイズの影響を受ける。

### 4.2 emotion_engine.py
- 実現性: 高い。
- 良い点: 数式が明示されているので、実装と検証がしやすい。
- 懸念: かなりルールベースなので、情動というより状態遷移器に近い。

### 4.3 dual_memory_system.py
- 実現性: 高い。
- 良い点: ChromaDB の採用は素直。
- 懸念: `retrieve_context` のランキング融合、重複排除、事実抽出の品質が肝。

### 4.4 conscious_agent.py
- 実現性: 中〜高。
- 良い点: `think` 相当の内部整列を促す設計は、推論モデルと相性がよい。
- 懸念: システムプロンプトで「必ず `<think>` を出せ」と強制すると、モデルや配信層によっては崩れることがある。

### 4.5 sleep_consolidation.py
- 実現性: 中。
- 良い点: `episode -> dream dataset -> SFT/QLoRA` の流れは研究プロトタイプとして分かりやすい。
- 懸念: 学習データ生成の自己循環で、誤りや偏りを増幅しやすい。
- 特に注意: `thought` の正解性をどう担保するかが最大の課題。

## 5. 実現可能性のざっくり評価
- すぐ作れる部分: 情動更新、双層記憶、会話ループ、簡易要約。
- 難しい部分: `loss` を基準にした安定した主観表現、睡眠学習の品質制御、自己生成 CoT の妥当性評価。
- 工数感: 小さな実験系なら数日〜1週間、研究として納得できる安定化にはかなり追加検証が要る。

## 6. 主なリスク
- 評価指標がないと「動いている」が「良くなっている」にならない。
- 長期記憶の汚染で、関係ない事実を保存し続ける危険がある。
- QLoRA の反復で性格がドリフトし、元の挙動が失われる可能性がある。
- `<think>` を外部化しすぎると、内部推論の安全性や一貫性が崩れる。

## 7. 最初の検証順
- 1) `EmotionEngineAllostasis` の数式単体テスト。
- 2) `DualMemorySystem` の保存・検索・統合の最小実装。
- 3) `ConsciousAgent` のプロンプト組み立て。
- 4) 睡眠学習は最後に回す。

## 8. 結論
- この案は「研究テーマ」としては強いが、最初からフル実装すると複雑すぎる。
- まずは記憶と情動のループを小さく閉じ、その後に睡眠学習を足すのがよさそう。
