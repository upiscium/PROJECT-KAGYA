# Multimodal FastAPI Interface - Idea Review

## 対象
画像、音声、動画、テキストを送れる FastAPI ベースの入力インタフェース。

## 何を解くか
- ひとつの API で複数モダリティを受け取りたい。
- 画像・音声・動画・テキストを別々に扱うのではなく、統一された入口にしたい。
- 将来的に推論、記憶、検索、対話へつなげやすくしたい。

## 良い点
- FastAPI は型付きの入力設計がしやすい。
- `multipart/form-data` と JSON を組み合わせやすい。
- テキスト中心、ファイル中心、ストリーミングを分けて設計しやすい。

## 先行事例との近さ
- REST + UploadFile + WebSocket の一般的な構成に近い。
- マルチモーダル入力の入り口としてはかなり素直。

## リスク
- 動画はサイズが大きく、直接送信すると重い。
- 音声・動画の前処理を API に入れすぎると遅くなる。
- モダリティごとに入力スキーマがぶれると保守しづらい。
- 単一エンドポイントに全部入れると責務が混ざる。

## 実現性
- 実現性: 高い。
- 難易度: 低〜中。
- 工数感: 小〜中。

## 実装時の注意
- テキスト / ファイル / ストリーミングを分ける。
- 動画はサイズ制限を先に決める。
- 受信後の非同期処理を API 本体から外す。
- まずは入力正規化層を挟む。

## 現実的な構成
1. `POST /ingest` で text + files を受ける
2. `POST /chat` でテキスト対話を受ける
3. `WS /stream` で逐次応答する
4. 画像・音声・動画は後段の処理に渡す

## 結論
- FastAPI はこの用途にかなり向いている。
- ただし、最初から全部を1本に詰め込まず、モダリティごとに責務を分けるのがよい。
